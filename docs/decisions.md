| 8 | 2026-07-21 | Recommended mode appends `-bis` to the auto tag name; import button relabels | A BIS tab is a different artifact from the adaptive tab; without this, importing in the mode silently overwrites the tab imported minutes earlier under the same generated name |
| 9 | 2026-07-22 | Gear↔inventory pairing is read from the page's **template order**, not their labels; label matching is the fallback. Pairing is refused outright when the template counts disagree with the parsed models, or when the order is ragged | Half the pages head every inventory `==Inventory==`, so labels can't distinguish them, while order is unambiguous. A wrong pairing silently loads the wrong inventory, which is worse than none — so ambiguity must fail closed |
| 10 | 2026-07-22 | Repeated dropdown labels get a `(2)`, `(3)` suffix rather than being merged or hidden | Pages really do list two different setups under one `|style=`. Both are legitimate content; the suffix keeps both reachable and, because the tag name is slugged from the label, stops the second import replacing the first tab |
| 11 | 2026-07-22 | Importing over an existing tag always asks, including over the plugin's own tabs; the dialog distinguishes them and defaults to Cancel | User requirement. Re-import is the normal refresh path, so a bare "are you sure" would train people to click through — naming whose tab it is keeps the warning meaningful for the case that can't be undone (a hand-arranged layout) |
| 12 | 2026-07-23 | **"Show wiki BIS" stays exactly true to the wiki.** No change may make BIS show, hide, reorder, or substitute an item based on what the player owns. Consequences: switch/annotation setups (W3) route through the owned-only extras channel, so they never appear in BIS; the only ownership touch permitted is placing the player's owned variant id of the *same* item so the tab is clickable. BIS still honours the wiki's own conditions — a task-conditional rank-1 is skipped when the "On this task" checkbox is off (confirmed by user), because that is the wiki's condition, not an ownership fact | User directive. BIS is the "what does the wiki actually say" view; the moment ownership leaks in, it stops answering that question. This is also why W1's off-task guards matter for BIS specifically — the four false-positive slayer flags currently drop items the wiki lists as rank 1 |
